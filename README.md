# Construction Stock Management System

A Spring Boot REST API for managing construction sites, stores, storekeepers, material categories, stock issues, and issued materials.

- Spring Data JPA / Hibernate
- PostgreSQL
- Maven

## Prerequisites

- JDK 17 or newer
- PostgreSQL
- Git (to clone the repository)

## Configure PostgreSQL

Create the database used by the default application configuration:

```sql
CREATE DATABASE constructionstock;
```

Configure the connection using environment variables. For PowerShell:

```powershell
$env:DB_URL = "jdbc:postgresql://localhost:5432/constructionstock"
$env:DB_USERNAME = "postgres"
$env:DB_PASSWORD = "your-postgres-password"
```

Alternatively, create an ignored `application-local.properties` file in the project root and set your local `spring.datasource.url`, `spring.datasource.username`, and `spring.datasource.password` values there. Do not commit credentials.

Hibernate is configured with `ddl-auto=update`; it creates or updates the entity tables when the application starts. SQL logging is enabled.

## Run the application

Clone the repository and move into the project directory:

```powershell
git clone https://github.com/Edosine-dev/construction-stock-management-system-backend.git
Set-Location construction-stock-management-system-backend
```

After setting the database configuration, start the API with the Maven wrapper:

```powershell
.\mvnw.cmd spring-boot:run
```

The API listens at `http://localhost:8080`. Leave this process running while sending requests from Postman or another HTTP client.

Run the test suite with:

```powershell
.\mvnw.cmd test
```

## API overview

All routes use the `/api` prefix. Create and update requests accept JSON bodies. UUID IDs are generated by the API.

### CRUD resources

| Resource | Base path |
|---|---|
| Material categories | `/api/material-categories` |
| Stores | `/api/stores` |
| Storekeepers | `/api/storekeepers` |
| Construction sites | `/api/construction-sites` |
| Stock issues | `/api/stock-issues` |

Each CRUD resource supports:

| Method | Route | Description |
|---|---|---|
| `POST` | `{base-path}/save` | Create a record |
| `GET` | `{base-path}/all` | List records |
| `GET` | `{base-path}/{id}` | Get a record by UUID |
| `PUT` | `{base-path}/update/{id}` | Update a record |
| `DELETE` | `{base-path}/delete/{id}` | Delete a record |

Stock issue deletion is rejected while issued materials are linked to it. Stock issue status changes must use the dedicated status endpoint.

### Queries and business operations

| Method | Route | Parameters / purpose |
|---|---|---|
| `GET` | `/api/construction-sites/by-location` | `location`; case-insensitive site search |
| `GET` | `/api/construction-sites/of-storekeeper/{storekeeperId}` | Sites with stock issues handled by the storekeeper |
| `GET` | `/api/storekeepers/by-material-category` | `name`; search by material category |
| `GET` | `/api/stores/free` | List unoccupied stores |
| `GET` | `/api/material-categories/unused` | List categories held by no storekeeper |
| `GET` | `/api/stock-issues/by-status` | `status` enum value |
| `GET` | `/api/stock-issues/between` | `start` and `end` dates (`YYYY-MM-DD`) |
| `PATCH` | `/api/stock-issues/{id}/status` | `status` enum value |
| `PUT` | `/api/storekeepers/{storekeeperId}/material-categories/{materialCategoryId}` | Add a category to a storekeeper |
| `PATCH` | `/api/storekeepers/{storekeeperId}/store` | `storeNumber`; move a storekeeper |
| `POST` | `/api/issued-materials/save` | `stockIssueId` query parameter and issued-material JSON body |
| `GET` | `/api/issued-materials/construction-site/{siteCode}` | Issued-material history for a site |
| `DELETE` | `/api/issued-materials/delete/{id}` | Delete an issued material |
| `GET` | `/api/stock-issues/stats/by-status` | Count stock issues grouped by status |
| `PATCH` | `/api/stock-issues/cancel-day` | `storekeeperId` and `date` (`YYYY-MM-DD`) |
| `GET` | `/api/dashboard/summary` | Dashboard totals |
| `GET` | `/api/stock-issues/page` | `page`, `size`, and `sort` (for example `issueDate,desc`) |

## Create records in Postman

Set the request header to `Content-Type: application/json`. For example, create a construction site:

```http
POST http://localhost:8080/api/construction-sites/save
```

```json
{
  "siteName": "Kigali Heights",
  "foremanName": "Jean Niyonzima",
  "siteCode": "SITE-08",
  "location": "Kicukiro"
}
```

Create related records in dependency order: stores and material categories first, then storekeepers referencing them, construction sites, and finally stock issues referencing a site and storekeeper. Issued materials can only be recorded for stock issues whose status is `ISSUED`.
